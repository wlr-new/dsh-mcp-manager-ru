# dsh-mcp-manager

[Русский](README.ru.md) · [English](README.md)

> **Менеджер MCP-серверов для DeepSeek Harness**: добавляйте, удаляйте и изменяйте MCP-серверы на Web-странице настроек или напрямую через инструменты agent —
> **подключение и отключение выполняются в рантайме, без перезапуска DSH**.

`@zhengjunyao/dsh-mcp-manager` · MIT · требуется DSH `>= 0.1.5-rc.1` · Node `^22.19.0 || >=24.0.0`

---

## Для чего это нужно

MCP-сервер обычно приходится прописывать в композиции harness (слой `cordis.yml`), чтобы он загрузился, и любое изменение требует перезапуска хоста.
Этот плагин превращает «какие MCP-серверы есть» в обычный JSON-файл, которым можно управлять в рантайме:

- на странице настроек одним кликом **добавить / изменить / включить-выключить / протестировать / удалить** сервер;
- инструменты `mcp_manager_*` позволяют agent сделать то же самое;
- инструменты сервера как обычно появляются в сессии под именами `mcp__<имя_сервера>__<имя_инструмента>`;
- отключение или удаление **немедльно снимает** инструменты этого сервера — перезапуск не нужен.

Два транспорта: **stdio** (локальный процесс, `command` / `args` / `env` / `cwd`) и
**Streamable HTTP** (удалённый URL, `url` / `headers`).

## Начало работы

> **Перезапуск DSH не нужен на каждом шаге.** После установки в профиль хост сам пересобирает дерево плагинов (при невыставленном `dsh.profile.patchReload` это live-reload) — достаточно **обновить страницу браузера**, чтобы увидеть панель.

1. **Установите плагин** — выполните:

   ```bash
   dsh plugin --profile web add @zhengjunyao/dsh-mcp-manager
   # из исходников: dsh plugin --profile web add link:/path/to/dsh-mcp-manager
   ```

   Ожидаемо: команда завершается строкой `+ @zhengjunyao/dsh-mcp-manager`, а пакет появляется и в зависимостях, и в списке загрузки профиля.

2. **Откройте «Управление MCP» на странице настроек** — обновите Web GUI → слева откройте **Настройки** → найдите карточку **«Управление MCP»**.

   Ожидаемо: в карточке есть главный переключатель, список серверов, и у каждого сервера — значок состояния (`active` / `starting` / `waiting` / `error` / `stopped`).

> 📷 **[Место для скриншота 2]Стартовый экран: где находится карточка «Управление MCP» и как она выглядит**
> Как снять: обновить Web GUI → слева открыть «Настройки» → прокрутить до карточки «Управление MCP» → остановиться, когда вся карточка видна целиком (заголовок + главный переключатель + список серверов в одном кадре)
> Конфиденциальность: если серверы уже есть — **зачернить имена серверов и локальные пути в командах**
> Замена: подставить вместо этого блока `![Карточка настроек MCP-менеджера](адрес_картинки)`

3. **Добавьте сервер** — нажмите **Добавить сервер** в карточке, задайте имя (оно станет префиксом инструментов `mcp__<имя>__`), выберите транспорт (для stdio — команда, для Streamable HTTP — URL) и сохраните.

   Ожидаемо: новый сервер сразу появляется в списке, значок состояния проходит путь от `starting` к `active`; при ошибке остаётся на `error`, а рядом показана причина.

> 📷 **[Место для скриншота 3]Ключевое действие: как выглядит форма добавления и что в ней заполнять**
> Как снять: нажать «Добавить сервер» → раскрыть форму и заполнить (имя + транспорт + команда/URL) → остановиться до сохранения
> Конфиденциальность: **локальные пути, домены и токены** в команде или URL — зачернить обязательно
> Замена: подставить вместо этого блока `![Добавление MCP-сервера](адрес_картинки)`

4. **Убедитесь, что инструменты реально зарегистрированы** — посмотрите **число инструментов** у сервера и разверните список имён; либо попросите agent вызвать `mcp_manager_list`.

   Ожидаемо: число инструментов > 0, имена вида `mcp__<имя>__<инструмент>`, и эти инструменты **могут быть вызваны agent сразу**.

> 📷 **[Место для скриншота 4]Шаг, на котором чаще всего застревают: доказательство «подключился и зарегистрировал инструменты»**
> Как снять: сервер в состоянии `active` → развернуть список его инструментов → остановиться в момент, когда **одновременно видны значок, число инструментов и несколько имён вида `mcp__…__…`**
> Конфиденциальность: имена инструментов обычно можно оставить; имена серверов и пути с личными данными — зачернить
> Замена: подставить вместо этого блока `![Сервер подключён, инструменты зарегистрированы](адрес_картинки)`

5. **Протестируйте подключение** (необязательно, но рекомендуется) — нажмите **Тест** у сервера или попросите agent вызвать `mcp_manager_test`; поддерживается также пробный запуск **черновика**, который никуда не сохраняется.

   Ожидаемо: при успехе — сообщение об успехе; при ошибке — причина (команда не найдена / порт закрыт / сбой авторизации и т. п.), чтобы можно было сразу исправить.

> 📷 **[Место для скриншота 5]Итог: сервер от конфигурации до рабочего состояния**
> Как снять: остановить на сообщении об успехе после теста (или на стороне agent — на ответе `mcp_manager_list`)
> Конфиденциальность: не требуется (URL/токены, если есть, зачернить)
> Замена: подставить вместо этого блока `![Тест подключения успешен](адрес_картинки)`

## Использование

### Страница настроек

Web GUI → Настройки → **«Управление MCP»**. В карточке можно:

- видеть живое состояние каждого сервера: `● Подключено` / `◌ Нет инструментов` / `✖ Ошибка` / `○ Не подключён`, а также число выданных им инструментов;
- развернуть список зарегистрированных имён инструментов;
- кнопка «Проверить соединение (без сохранения)» **реально подключается** и затем выбрасывает черновик — так опечатка ловится до сохранения;
- одной кнопкой «Импортировать из старого менеджера» перенести старые конфигурации.

### Инструменты agent

| Инструмент | Что делает |
| --- | --- |
| `mcp_manager_status` | Обзор: сколько серверов, сколько подключено, сколько инструментов всего, откуда загружен мост, где файл состояния |
| `mcp_manager_list` | Этап каждого сервера, имена инструментов, последние ошибки |
| `mcp_manager_add` | Добавить и сразу подключить |
| `mcp_manager_update` | Изменить любые поля, включить/выключить, переименовать |
| `mcp_manager_remove` | Удалить. **Без `confirm` — только предпроверка**, настоящее удаление после подтверждения |
| `mcp_manager_test` | Тест сохранённого сервера или пробное подключение черновика (без сохранения) |
| `mcp_manager_import` | Импорт из файла конфигурации другого MCP-менеджера (однократные имена не перезаписываются) |
| `mcp_manager_reload` | Перечитать файл конфигурации и переподключиться |

### Файл конфигурации

`$DSH_HOME/dsh-mcp-manager.json` (по умолчанию `~/.dsh/dsh-mcp-manager.json`, права 0600).
**Учитывает `DSH_HOME`**: машина с перенесённым home читает файл в новом месте. Можно редактировать вручную — после этого нажмите «Перечитать конфигурацию».

```json
{
  "version": 1,
  "config": { "enabled": true, "announceToAgent": true },
  "servers": [
    {
      "name": "garmin",
      "transport": "stdio",
      "enabled": true,
      "description": "Данные Garmin Connect о здоровье (только чтение)",
      "command": "/opt/homebrew/bin/uvx",
      "args": ["garmin-mcp"],
      "env": {},
      "cwd": "",
      "url": "",
      "headers": {},
      "toolCallTimeoutMs": 60000,
      "reconnect": {}
    }
  ]
}
```

`name` становится пространством имён инструментов: в примере выше инструменты называются `mcp__garmin__<инструмент>`.
Допустимы только буквы / цифры / подчёркивание / дефис, длина 1–32 — то же ограничение, что и у harness.

## Два переключателя

| Переключатель | Где | Что происходит при выключении |
| --- | --- | --- |
| установки | строка композиции профиля (`cordis.patch.yml`) | плагин ничего не монтирует: нет ни инструментов, ни панели |
| рантайма | файл конфигурации / кнопка «Отключить плагин» в панели | отключаются все MCP-серверы, снимаются с регистрации все инструменты `mcp__*`; **панель и `mcp_manager_*` остаются**, чтобы можно было снова включить |

## Дизайн: почему плагин сам не реализует MCP

Плагин **не переизобретает протокол** — он управляет мостом, который уже входит в harness,
`@deepseek-ai/dsh-mcp-client`: один включённый сервер = один экземпляр моста, отключение = уничтожение этого экземпляра.

Мост отвечает за транспорт stdio / Streamable HTTP, очистку учётных данных, повторные подключения с экспоненциальной задержкой, публикацию ресурсов и
договор об именах `mcp__<serverName>__<toolName>`. Плагин лишь решает «какие экземпляры должны существовать».

Разрешение — **лестница** (`src/core-mcp.ts`): в приоритете копия моста, которую использует **рабочий harness**,
и только если её не видно — запасной экземпляр из дерева зависимостей плагина. Разбег версий — классическая ловушка плагинов, таскающих собственный клиент.

### Почему мы вообще не трогаем `tools.restrict()`

npm-пакет, который заменяет этот плагин (`@wingsky-1/dsh-mcp-manager`), согласовывал видимость инструментов вызовами
**для каждого имени инструмента** ядрового `tools.restrict()`. А каждый такой вызов пересчитывает весь registry view заново
(создавая новые Map / Set), и стоимость получалась O(инструменты × имена²) — всё это легло на event loop хоста:
в замерах 94.7% CPU, порт без ответа 8 секунд, JS-куча 1080 MB.

Этот плагин **никогда не вызывает `restrict()`**: подключение регистрирует инструменты, отключение — снимает их; это и есть контракт моста.
Единственное чтение реестра — один вызов `ctx.tools.schemas()` на каждое наблюдение с группировкой в памяти по префиксу:
затраты линейны и оплачиваются только тогда, когда панель или инструмент статуса действительно смотрит.

## Проверки

```bash
npm run typecheck
npm test                 # 54 unit-теста
npm run verify:live      # реальный экземпляр, end-to-end (настоящий stdio MCP-сервер → инструменты mcp__*)
npm run verify:full      # гейт переносимости (изолированный DSH_HOME + установка из tarball)
```

`npm run verify:live` поднимает **изолированный** экземпляр DSH (свой `DSH_HOME`, ваша установка не трогается),
внутри него реально запускает `tests/fixtures/echo-mcp-server.mjs` (рукописный MCP-сервер без зависимостей,
чтобы «обе стороны подтвердили друг другу один и тот же сломанный формат» было невозможно) и проверяет:

1. сервер из стартовой конфигурации переходит в `active`, инструменты — `mcp__echo__echo` / `mcp__echo__add`;
2. добавление второго сервера через HTTP → его инструменты появляются;
3. отключение → его инструменты **немедленно исчезают** (это и есть измерение «без перезапуска»);
4. удаление → определение исчезает из конфигурации;
5. пробный запуск черновика сообщает об инструментах, но **не пишет на диск**, а исходный сервер восстанавливает подключение;
6. выключение главного переключателя → все `mcp__*` снимаются с регистрации, управляющие инструменты остаются; включение → всё возвращается.

## Совместимость

- DSH `>= 0.1.5-rc.1` (проверено на `0.1.7-rc.2`).
- Требуется встроенный в harness пакет `@deepseek-ai/dsh-mcp-client`; при отсутствии плагин **запускается как обычно**,
  панель и `/probe` честно сообщают `bridgeError`, не роняя хост.
- Работает на macOS / Linux / Windows (для stdio — абсолютный путь в `command`; на Windows не забудьте суффикс `.cmd`). **С этой версии** в `peerDependencies` явно объявлена совместимость с **DSH 0.2.0-rc.2** (`^0.2.0-rc.2` теперь входит в диапазон), так что предупреждение о совместимости на 0.2.0-rc.2 больше не появляется; функциональность и поведение без изменений.
